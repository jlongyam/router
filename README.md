# Router

A hash based Router

## But why?

The the difference of this router with other hash router
is have ability to **parse sub slash after query**,

example

> `#page/test?asset=/path/to/file.js`

That slash after querty parsed properly.

## Features

- simple -> focuc to hash only
- small -> under 100 lines of code
- query friedly -> explained above
- typed -> ships its own type definitions, no `@types/*` needed
- ready to use -> `import router from '@jlbyte/router'`, no `new Router()`
- `router.match` -> work in node and browser
- `router.route` -> work in browser

## Usage

<details name="usage">

<summary>Design site map</summary>

Import

```js
import router from '@jlbyte/router'
```

1. **Basic** design

```js
console.dir( router.match('#index', ':page') );
```

```js
{ path: 'index', params: { page: 'index' }, query: {} }
```

2. **Complex** design

```js
console.dir( router.match('#page/test?asset=path/to/file.js', 'page/:any') );
```

```js
{
  path: 'page/test',
  params: { '$0': 'test' },
  query: { asset: 'path/to/file.js' }
}
```

See usage detail in **usage/design.mjs**

</details>

<summary>Test design</summary>

Example:

```js

let hash = '#lib/test/src?path=./root/file.css'
let pattern = 'lib/:n/src' 
 

let result = { 
  path: 'lib/test/src',
  params: { n: 'test' },
  query: { path: './root/file.css' }
}

console.assert( router.match( hash, pattern ), result )
```

</details>
<details name="usage">

<summary>Create route</summary>

Design:

```js
console.dir( router.match('#style/load?file=style.css', 'style/:action') )
```

Result:

```js
{
  path: 'style/load',
  params: { action: 'load' },
  query: { file: 'style.css' }
}
```

Implementation:

```js 
router.route('style/:action', ({ params, query })=> {
  if(params.action === 'load') {
    console.log( query.file )
  }
})
```

</details>

## TypeScript

Type definitions are bundled, so editors and `tsc` pick them up without
installing anything extra:

```ts
import router from '@jlbyte/router'
import type { MatchResult, RouteMatch } from '@jlbyte/router'

const parsed: MatchResult | null = router.match('#page/test', 'page/:any')
```

## Module format

Two entry points:

- `import` -> `src/router.mjs`, native ESM shipped as source (no build). Its
  single default export is the ready-made `router`.
- classic `<script>` -> `dist/router.js`, an IIFE that registers `window.router`
  automatically (the `Router` class is not exposed globally).

```html
<script src="https://cdn.jsdelivr.net/npm/@jlbyte/router/dist/router.js"></script>
<script>
  router.route(':page', ({ params }) => console.log(params.page))
  router.navigate('#home')
</script>
```

No wiring is needed with the script tag: `router` is already global.

### Legacy build

`dist/router.legacy.js` is the same router transpiled to ES5, for engines that
predate ES2015 (for example the QtWebKit-based Otter Browser). Only **syntax** is
transpiled — load your polyfills first for `Map`, `Symbol.iterator`,
`Object.entries` and `String.prototype.startsWith`:

```html
<script src="polyfills.js"></script>
<script src="https://cdn.jsdelivr.net/npm/@jlbyte/router/dist/router.legacy.js"></script>
<script>
  router.route(':page', ({ params }) => console.log(params.page))
</script>
```

`dist/` is generated by `pnpm build` (rollup) and is not committed.

## Development

Node **20** is the target (see `.nvmrc`): it is the last line that still ships
32-bit `linux-armv7l` builds.

```bash
nvm use            # reads .nvmrc
pnpm install
pnpm test          # builds dist/, then runs the uvu suite
pnpm typecheck
pnpm build         # dist/router.js + dist/router.legacy.js
```
